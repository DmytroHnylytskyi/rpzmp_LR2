# AeroGrid 2.0 — Вітрова електростанція з моніторингом швидкості вітру

Мобільний застосунок на Android для диспетчерського SCADA-моніторингу вітрової електростанції, інженерного моделювання та локального збереження телеметрії. Розвиток застосунку з ЛР №1: додано навігацію між екранами, складні форми, архітектуру MVVM та локальну реляційну базу даних.

## Загальна інформація

* **Дисципліна:** Розробка програмного забезпечення мобільних пристроїв
* **Університет:** Національний технічний університет України «Київський політехнічний інститут імені Ігоря Сікорського»
* **Кафедра:** Кафедра інженерії програмного забезпечення в енергетиці
* **Практична робота:** №2 (завдання №5–8)
* **Варіант:** №2 — «Вітрова електростанція з моніторингом швидкості вітру»

## Можливості застосунку

### Навігація та головне меню

* Jetpack Navigation Component з типізованими маршрутами (`sealed class Screen`) та 9 екранами в єдиному NavHost.
* Передача даних між екранами через аргументи маршруту: ім'я чергового інженера (`{userName}` — `NavType.StringType`) та кількість діючих турбін (`{turbinesCount}` — `NavType.IntType`).
* Нижня панель навігації з п'ятьма розділами (моніторинг, телеметрія, прогноз, база даних, диспетчер) із збереженням стану стеку.
* Адаптивний інтерфейс: `BoxWithConstraints` перемикає компонування кнопок між вертикальним (смартфон) та горизонтальним (планшет) представленням.

### Форми введення даних

* Спільний модуль валідації `Validators` — єдина логіка для екранів та модульних тестів.
* Форма реєстрації станції: назва, email за регулярним виразом, пароль із маскуванням, динамічним індикатором надійності та перевіркою складності (≥ 8 символів, велика літера, цифра), потужність у межах діапазону; підказки та повідомлення про помилки під кожним полем.
* Форми доступу персоналу: вхід лише для зареєстрованих диспетчерів з розмежованими помилками («обліковий запис не знайдено» / «невірний пароль»).
* Асинхронна відправка через корутини з індикаторами завантаження.

### Архітектура MVVM та SCADA-телеметрія

* Шар представления (`TelemetryMvvmScreen`), логіка (`WindTelemetryViewModel` з `StateFlow`/`collectAsState`) та чиста фізична модель парку (`WindParkModel`, покрита тестами):
  * Штиль (v < 3.0 м/с) — ротор зупинено, нижче Cut-in;
  * Оптимальна генерація (3.0–12.0 м/с) — кубічний закон Беца P ~ v³ (MPPT);
  * Номінальний режим (12.0–25.0 м/с) — Pitch-контроль утримує 17.0 МВт (5 × 3.4 МВт);
  * Штормовий захист (v > 25.0 м/с) — аварійне гальмування Cut-out.
* Повний набір станів: завантаження (опитування давачів), успіх та помилка телеметричного каналу з повторним запитом.

### Керування парком турбін

* Диспетчерський CRUD вітроустановок з ЛР №1: додавання, редагування паспортних даних, видалення з підтвердженням.
* Активне спільне джерело даних `TurbineFleet` — зміна складу парку миттєво перераховує телеметрію та сумарну генерацію на всіх екранах.

### Локальна база даних Room

* Багатотаблична реляційна схема: батьківська таблиця `wind_stations` з дочірніми таблицями телеметрії (потужності, швидкості вітру, напруги) через `@ForeignKey` з каскадним видаленням та індексами.
* Атомарна транзакція вставки станції разом з усіма масивами телеметрії (`@Transaction`).
* Реактивне відображення даних через Room `Flow`: списки, історії телеметрії та аналітика (`SELECT AVG`) оновлюють UI автоматично після кожної операції.
* Пошук станцій за назвою/локацією та сортування за назвою або встановленою потужністю.
* База стартує чистою — без демонстраційних записів; підтвердження видалення з каскадом та повідомлення про результати операцій.

### Доступ оперативного персоналу

* Облікові записи диспетчерів у таблиці `wind_dispatchers` (Room, міграція 1→2): унікальний логін/email, пароль лише у вигляді SHA-256 хеша.
* Реєстрація з перевіркою унікальності, збереження закріпленої зміни та налаштування SMS-сповіщень (RadioButton, Switch, Checkbox).

## Технології

* **Мова:** Kotlin 2.2.10
* **Платформа:** Android (minSdk 24, targetSdk 37)
* **UI:** Jetpack Compose (BOM 2026.02.01), Material Design 3, темна тема Eco-Tech
* **Навігація:** Jetpack Navigation Compose 2.8.7
* **Архітектура:** MVVM — Lifecycle ViewModel Compose 2.8.7, StateFlow, Coroutines
* **База даних:** Room 2.7.2 + KSP 2.2.10-2.0.2
* **Тестування:** JUnit 4 (`ModulesTest`, `DispatcherAuthRepositoryTest`, `WindPowerCalculatorTest`)

## Збірка та запуск

1. Відкрити проєкт в Android Studio та дочекатися синхронізації Gradle.
2. Запустити модульні тести:
```bash
./gradlew testDebugUnitTest
```
3. Зібрати та встановити застосунок на підключений пристрій або емулятор:
```bash
./gradlew installDebug
```
